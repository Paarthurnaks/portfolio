# CRM-система: замена Bitrix24 под конкретного клиента

> **Коротко.** CRM под ключ для одного клиента, которому не подошёл Bitrix24: лиды и сделки, воронки и канбан, динамические поля карточек, задачи, чаты, комментарии с таймлайном, поиск по всем сущностям, права доступа (ABAC/RBAC), аналитика, генератор документов и вебхуки.
> Я руководил backend-частью и лично делал генератор отчётов и документов. Проект вышел в релиз, им пользуются сотрудники одной организации.

## Контекст

Клиенту нужна была CRM в стиле Bitrix24, но с собственной логикой и без ограничений облачного сервиса. Основной сценарий: работа с лидами и сделками, ведение клиентов и задач, общение по карточкам и формирование документов.

Часть решений принималась в режиме «быстро выйти в релиз, а развитие оставить на потом». Ниже я отдельно отмечаю, где мы сознательно упростили реализацию.

## Решения и результаты

### 1. Динамические поля карточек

**Проблема.** В Bitrix24 пользователь сам добавляет поля и разделы в карточку. Клиенту нужно то же самое, причём для разных сущностей.

**Решение.** Поля хранятся в отдельных таблицах: описание поля, привязка поля к сущности и значение поля для конкретной записи. Благодаря этому набор полей меняется без миграций и релизов.

**Результат.** Пользователь настраивает карточки лидов, сделок и клиентов сам. Отчёты и документы могут использовать эти поля наравне со стандартными.

### 2. Генератор документов

**Проблема.** Пользователям нужны документы (договоры, акты и другие) со значениями из карточек, причём шаблоны должны меняться без участия разработчика.

**Решение.** Шаблон — обычный `docx`-файл с метками вида `{{deal.title}}` или `{{lead.user_field_1}}`. Пользователь видит в интерфейсе список кодов и их значений и вставляет их в нужные места. На backend шаблон читается через PHPWord, и встроенная функция подмены заменяет метки значениями из массива данных одной командой.

**Результат.** Документы формируются из шаблонов, которые пользователи ведут сами.

**Что мы сознательно оставили на потом.** Печати и подписи автоматом не подставлялись: для первого релиза решили, что пользователи заранее вставляют изображение печати прямо в шаблон `docx`.

### 3. Конструктор отчётов

**Проблема.** Руководителям нужны отчёты по сделкам и другим сущностям, и каждый раз просить разработчика собрать новую выборку нельзя.

**Решение.** Сделал конструктор отчётов по образцу Bitrix24. Пользователь выбирает сущность (например, сделки) и название отчёта («отчёт по менеджерам за месяц»), затем задаёт условия. Условия строятся на логике И и ИЛИ с вложенными подусловиями: например, «Ответственный» — «Группа пользователей» — «Менеджеры» и «Дата» — «Последний месяц». После этого выбираются поля для вывода (сумма, менеджер, клиент, дата) и по кнопке «Сформировать» создаётся xlsx-файл с детализацией.

**Результат.** Пользователи собирают нужные отчёты сами, без участия разработчика.

### 4. Real-time: чаты, комментарии и уведомления

**Проблема.** Общение по сделкам должно быть живым, а комментарии должны попадать в ленту карточки сразу.

**Решение.** Чаты, комментарии с таймлайном и уведомления работают на Socket.io.

**Результат.** Пользователь видит новые сообщения и обновления без перезагрузки страницы.

### 5. Поиск: упростили ради релиза

**Проблема.** Нужен поиск по всем сущностям CRM.

**Решение.** Для релиза сделали простой поиск по нескольким таблицам без отдельного поискового движка. Поисковый движок и отдельные поля с поисковыми фразами в БД сознательно отложили.

**Результат.** Поиск работал в первом релизе без лишней инфраструктуры. Осознанный компромисс: он будет медленнее на больших базах, поэтому усиление поиска остаётся в планах (см. «Точки роста»).

## Права доступа

ABAC и RBAC построены на основе `spatie/laravel-permission`. Это знакомый мне инструмент, особых сложностей не было.

---

## Точки роста

- **Поиск.** Нужен поисковый движок или хотя бы отдельные денормализованные поля с поисковыми фразами. Сейчас поиск идёт по нескольким таблицам напрямую.
- **Масштаб.** Это внутренняя CRM одной организации: ей пользуются только сотрудники этой организации, поэтому больших цифр по нагрузке у проекта нет.
- **Печати в документах.** Автоматическая подстановка печатей и подписей остаётся на будущее.
