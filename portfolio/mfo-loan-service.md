# Сервис выдачи займов: Госуслуги, скоринг и КриптоПро

> **Коротко.** Новый сервис выдачи займов для микрофинансовой организации: заявка с авторизацией через Госуслуги, многоступенчатый скоринг (НБКИ, Росфинмониторинг, паспорт, банкротство), график платежей, рекуррентные списания, возвраты и интеграция с 1С.
> Я руководил разработкой и лично реализовал КриптоПро, Госуслуги и все проверки. К моменту моего ухода из команды сервис ещё не был запущен, поэтому в этом кейсе нет боевых цифр.

## Контекст

Микрофинансовая организация делала свой сервис выдачи займов и кредитов. Для пользователя это выглядело как лендинг, где нужно пройти несколько этапов заполнения анкеты. Всё остальное происходило на backend: проверки по внешним источникам, скоринг, график платежей и работа с платёжными системами.

Сервис проектировался на том же уровне нагрузки, что и [экосистема микрокредитования](mkk-ecosystem.md): после запуска планировалось перевести на него весь трафик экосистемы и закупку лидов у лидогенераторов.

## Решения и результаты

### 1. Проверка паспорта: гигабайтный файл

**Проблема.** Действительность паспорта проверялась по CSV-файлу, который ежедневно обновлялся по API. Он весил несколько гигабайт. Парсить такой файл в базу данных долго и неудобно.

**Решение.** Использовал то, что файл обычный текст, и искал по нему напрямую через `grep`, не загружая данные в БД.

**Результат.** Поиск по файлу работает очень быстро, а ежедневное обновление не превращается в долгую перезагрузку таблицы.

### 2. Росфинмониторинг: нет API

**Проблема.** У Росфинмониторинга нет собственного API для проверки клиентов.

**Решение.** Написал парсер сайта, который выполняет проверку так же, как это делал бы человек.

**Результат.** Проверка по Росфинмониторингу стала частью автоматического скоринга.

### 3. НБКИ: подписанные запросы, битый XML и долгие согласования

**Проблема.** С НБКИ пришлось повозиться больше всего:
- запросы нужно подписывать через КриптоПро;
- их API отдаёт битый XML, который нужно выравнивать перед разбором;
- подписание и согласование сертификатов с их стороны занимало много времени.

**Решение.** Реализовал подпись запросов через КриптоПро и слой, который исправляет некорректный XML перед разбором. Время ожидания сертификатов закладывал в планы работ.

**Результат.** Интеграция с НБКИ стала частью скоринга. Это самая трудоёмкая проверка в проекте.
